# 手机链接的持久交付

所有本轮交付的手机页面、视频、下载和辅助预览链接，均使用 `on-mobile` 的系统托管服务或具备等效生命周期的托管服务。默认在 macOS 使用 `mobile-service.mjs` 的 launchd 入口。不要将 foreground 工具会话、shell 后台、`nohup` 或仅常驻的代理配置当作完整托管；源服务及所依赖的隧道都必须有可靠生命周期。

## 生成与验证

1. 将页面、视频及必要资源保存在可持续读取的交付目录，不能依赖会被临时清理的文件；只暴露交付内容。
2. 按已安装 `on-mobile` 技能，将实际媒体服务器命令交给 `mobile-service.mjs start --cwd <绝对目录> --port <空闲端口> -- <命令及参数>`。保留返回的真实服务 ID；已有端口要先核实托管及进程归属，不能接管别人的服务。
3. 用 `mobile-url-for-port.mjs <端口> --service <服务ID> --https` 取得入口。ngrok 同样需要生命周期覆盖本链接的托管 agent；不能只守护隧道、放任源服务随任务退出。
4. 启动命令结束后，重新核对服务仍运行、最终手机 URL 的页面/媒体可达、HTTPS、媒体类型及 Range 206。浏览器检查继续遵守静音规则，确认播放、拖动和章节正常；daemon 存活不替代媒体验收。
5. 交付链接、服务 ID、明确到期时间、回收方式和有效条件。本机仍须开机、唤醒、联网并保持所需登录；Tailscale 仍需对应设备接入。不能把 daemon 宣称为断电离线也可访问。

## 保留与回收

- 创建时记录固定的 7 天截止时间；用户明确说看完、用完或要求关闭时可提前回收，以先到者为准。一次访问、播放结束、浏览器关闭、闲置、助手完成或任务归档均不代表用户确认。
- 探测、任务恢复、服务重启不延长截止时间。不用聊天提醒代替服务侧自动到期；休眠或退出登录期间无法执行时，恢复后先检查到期，再决定是否启动。
- 回收使用 `mobile-service.mjs stop <服务ID>` 并核对 `status` 到 `closed`。`stopping`、`cleanup_failed` 不算已回收；失败保留回执和日志，重试明确属于自己的资源。
- 只关闭本链接拥有的服务及精确路由，不执行全局 Tailscale reset，不关闭共享 ngrok agent 或其他任务端点，不删除原片、成片、文档或源项目。
- 移动托管生命周期不延长录屏占用：验收后仍按原规则停止录制、关闭自有临时应用并交接桌面。此处 daemon 仅用于手机交付。
- 环境无法提供持续托管和自动回收时，报告具体缺口，不能将短命链接当成符合要求的交付。

## 恢复既有链接

断链、媒体缺失、worktree 删除或公网端点满额时，先按 `on-mobile` 的 `references/delivery-recovery.md` 盘点服务、原期限、文件与共享传输。用其配置驱动的 `mobile-delivery.mjs` 白名单文件服务和 `mobile-links.mjs` 审计；恢复服务通过 `start ... --inherit <原服务ID>` 保留原期限，不能重算七天。只在已验证归属的受支持网关挂独立子路径；既有自定义入口需验证保留旧路由的迁移方案，不为整合技能中断用户正在看的视频。

逐项核对原片/成片存在、非空、H.264/AAC、完整解码、实际视频 MIME 与 Range 206；必要时验证图册图片和内部跳转。首页 200 不代表视频可播放，审计脚本不代表手机浏览器已播放。共享代理存活不保证临时端点重启后恢复；无法保留同址、源文件丢失或期限证据不完整时明确报告，不借别的录像替代，也不关闭其他任务入口。
