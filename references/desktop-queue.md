# 共享桌面队列

队列协调同一台机器上的录屏验收。它不探测、不获取、不强制释放任何底层桌面资源，也不能约束未使用本流程的会话。所有参与者使用同一份状态，不能为绕开占用另建队列。

## 文件与身份

- 脚本：本技能的 `scripts/desktop_queue.py`，使用 `python3`，只依赖标准库。POSIX `flock` 让进程退出时自动释放短时写入锁，适用于本地 macOS/Linux 文件系统。
- 默认状态目录：`${CODEX_HOME:-$HOME/.codex}/state/computer-use/`，与项目、worktree 和技能副本无关。同一桌面的会话必须使用相同 CODEX_HOME；不得通过更换此变量绕过队列。`--state-dir` 仅用于隔离测试。
- `queue.json`：`current` 为当前协调占用（含 `thread_id`、`ticket`、`lease_id`），空闲为 `null`；`waiting` 按取号顺序记录 `thread_id`、`ticket`、`requested_at`；`notification` 保存当前队首的通知状态。
- `history.json`：`sessions` 按释放顺序保存每次协调占用的会话 ID、号码、凭据、申请/取得/释放时间和结果。它是队列占用历史，不证明实际界面操作或验收通过；撤销未使用的排队号码不计为使用。
- `.write.lock` 仅在读写 JSON 时加锁，等待或执行验收时不持有文件锁。锁文件留在原处，但系统锁已释放；不得删除它“解锁”。`.transaction.json` 是中断恢复日志，下次命令会在写入锁内重放同一次提交，使队列与历史一致，不另分配使用权。
- 脚本默认读取 `CODEX_THREAD_ID`。若缺失，从当前任务的可信元数据取得真实 ID 后传 `--thread-id`；不能猜测、使用别人的 ID，或把待创建任务的临时 clientThreadId 当成 threadId。环境已有 ID 时，脚本拒绝不一致的参数。

下列命令以 `QUEUE_TOOL` 表示本技能 `scripts/desktop_queue.py` 的实际绝对路径。执行前按本次技能安装位置设置该变量；技能搬迁时只调整脚本路径，不变更共享状态目录。所有命令返回 JSON，失败返回非零退出码；失败时禁止继续界面操作。

## 申请、等待、续用

```bash
python3 "$QUEUE_TOOL" request
```

- `result: acquired`：检查 `queue.current.thread_id` 是自己，保存返回的 `lease_id`。重复申请返回原号码和凭据，不重复入队。
- `result: waiting`：向用户说明号码、前方等待人数（`position - 1`）及当前使用会话。继续不占用桌面的准备工作，之后等待线程通知。若保持本轮活跃，可用可被新消息打断的等待工具每 30–60 秒休息一次，再运行 `status`；不得连续试用 共享桌面，也不得创建后台常驻轮询进程或擅自定时唤醒。
- 队首即使尚未收到通知，也可在 `status` 确认空闲后调用 `request` 接手；其他人只能留在原位。队首离线不会自动被跳过。停止等待任务时执行 `cancel`，不能悄悄遗留号码。
- 工具上下文恢复、收到通知或继续下一段界面操作前，检查本次凭据：

```bash
python3 "$QUEUE_TOOL" check --lease-id '<本次 lease_id>'
```

`check` 只核对协调占用，不能证明底层工具空闲。若工具报告另一会话仍在使用，保留自己的协调位置并报告实际阻塞，等待真实持有者释放；不要重新初始化/重置其他会话的工具、结束它的进程、替它释放资源或删除队列记录。若决定放弃本次验收，确认自己未持有实际工具后 `release --outcome backend_busy` 并通知下一位；不能反复释放再申请来争抢资源。

## 结束与取消

先停止本会话的录屏与待执行界面动作。若工具有明确的、仅针对自己的释放接口，调用该接口；没有时按其文档结束本会话使用，不臆造接口，也不用全局 reset 代替释放。随后执行：

```bash
python3 "$QUEUE_TOOL" release --lease-id '<本次 lease_id>'
```

错误或取消后的清理使用 `--outcome aborted`。只有当前会话和匹配的 `lease_id` 可以释放；重复释放同一凭据不会重复写历史，也不会释放后续占用。旧的清理动作不能释放同会话新一轮取得的凭据。

尚在等待时退出：

```bash
python3 "$QUEUE_TOOL" cancel
```

只能撤销自己。若取消的是空闲时的队首，脚本会为新的队首生成通知；正在使用者必须走 `release`。会话崩溃后写入文件锁由系统释放，但协调占用/等待号码不会自动过期。应由原会话恢复并清理；无法恢复时报告给用户核实处理，不自行驱逐。

## 必须完成的通知交接

脚本负责持久保存待通知记录，执行技能的会话负责调用线程消息工具；脚本本身不会连接 Codex 内部服务。**打印 `notify` 不等于已经发出通知。**

1. `release`、`cancel` 或后续检查返回非空 `notify` 时，使用其 `arguments` 调用 `mcp__codex_app__send_message_to_thread`。目标为记录里的 `threadId`，保留队列提供的通知 ID 与提醒文本，不带入前一个任务的私有内容，不改对方模型、标题或原任务范围。
2. 工具明确成功后，才登记该通知 ID：

```bash
python3 "$QUEUE_TOOL" notified --notification-id '<notify.id>'
```

3. 工具不可用、失败或结果不确定时，不执行 `notified`，报告“协调占用已释放，队首通知尚未确认”。待通知记录保留；恢复后先读取：

```bash
python3 "$QUEUE_TOOL" notifications
```

按当前返回的 `notify` 重试，不能缓存旧的收件人后向其反复发信。队首先自行接手/取消时，通知会失效；旧通知回执不会覆盖新通知。此流程允许“发送成功、登记前中断”造成同 ID 的重复通知，收件人必须检查当前任务仍需验收并重新核对队列，不能把每条通知当作新任务再次取号。

消息工具会向目标线程发送可见的后续消息以唤醒它；仅在真实交接中发送。测试使用隔离状态和模拟会话，不向真实的其他线程发送测试消息。

## 状态异常

```bash
python3 "$QUEUE_TOOL" status
```

写入锁忙时最多等 5 秒后退出，可稍后重试；禁止删锁或改占用。JSON 损坏、文件缺失或版本/顺序不一致时停止并保留证据，不把它当作空队列重建。无 TTL、自动回收、插队、代释放、force 或 reset 命令。队列遵守自愿协调原则，不是身份认证或权限隔离系统。

兼容性：历史路径 `computer_use_queue.py` 保留为同一实现的入口；状态目录中的 `computer-use` 仅为历史标识，不代表调用任何内置界面工具。不要迁移或重建状态。
