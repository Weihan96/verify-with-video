# 静音检查，保留交付声音

适用于录制、TTS、剪辑器预览、浏览器成片验收和章节播放。静音只作用于助手当前检查的播放器；不调整系统音量、不静音其他应用、不改变最终媒体音轨。用户明确要求外放试听时才可对该次指定素材听检。

## 合成与音轨验证

`edge-tts` 使用 `--write-media`；macOS 回退使用 `say -v Tingting -o "$AUDIO_FILE" "$TEXT"`。只生成文件并用 FFmpeg 混流，不调用 `edge-playback`、`afplay`、`ffplay` 或自动打开预览播放。剪辑器预览也先静音，保留导出音轨。

对最终交付 MP4 执行以下文件分析，无须声音输出设备：

```bash
ffprobe -v error -select_streams a -show_entries stream=index,codec_name,duration,sample_rate,channels -of json "$VIDEO"
ffmpeg -v error -xerror -i "$VIDEO" -map 0:a -f null -
ffmpeg -hide_banner -i "$VIDEO" -map 0:a -af volumedetect -f null -
```

确认预期音轨均存在且可完整解码；按旁白/原声映射检查起止、尾音、非全静音和音量统计。需要时解码为文件或绘制波形，不接音频输出。音轨保留与混流成功不等于已核对发音；准确写明检查方式。分析前后校验交付文件散列，防止误用无声副本。

## 浏览器播放前置条件

1. 使用该浏览器技能允许的播放器 UI 或控制接口，**先静音，再播放**。读取目标媒体实际 `muted` 状态或等价可靠状态；隐藏窗口、音量图标、此前一次静音都不是充分证据。不要为检查而绕过浏览器工具的只读限制。
2. 本任务生成的页面，应关闭自动播放，并在赋予媒体源或触发播放之前设置检查用静音状态。仓库实验页面 `experiments/cross_task/review_page.py` 支持 `?qa=muted`，仅该检查页面的播放器静音；普通用户链接不带这个参数且不自动播放。其他页面没有该开关时不能假设加参数就会生效。会自动有声播放、无法预先静音的页面不要打开试播，先准备受控检查入口或报告阻塞。
3. 首次播放、点击可能播放的章节、重新加载、切换媒体源或播放器节点前，重新确认静音。已知章节处理器会重置静音时先修正自己可修改的检查页面；不能先让它播出声，再依赖 `play`/`volumechange` 事件补静音。无法保证则停止该播放检查。
4. 每次章节跳转后核对仍静音、跳转位置正确；播放一小段并核对 `currentTime` 实际推进、画面对应章节。记录前后时间与静音状态。支持连续播放的页面还要覆盖播放中跳转；只检查暂停画面的 seek 不足以覆盖本次故障。
5. 重载后重新确认静音，再继续；完成后暂停并关闭自己的检查页。交付原 MP4 及普通用户入口，不在用户页面留下强制静音监听器，不把用户手动开启声音的能力永久禁用。

## 回归判定

使用含非静音音轨的多章节视频：助手首播、逐章点击、播放中跳转及重载后的再次播放均须在已确认静音的目标播放器内完成，且时间推进与关键画面正常。另以暂停状态检查普通交付入口未强制静音，离线确认同一 MP4 音轨非空且完整解码；不为了证明用户能听见而自动外放。全过程不修改系统或其他应用的音量。
